# Отчёт об использовании ИИ-ассистентов

## Что использовали
Claude Code (капитан: архитектура, ядро, очередь, слой модели, авторизация, документация, ревью), Codex/GPT (интерфейсы),
Gemini (стенд и локальная модель; на площадке работал ограниченно), DeepSeek — запасной вариант.
Координация — через файлы задач в `coord/tasks/` и общие правила в `AGENTS.md`; история в git показывает, кто что делал.

## Что генерировалось
- Каркас бэкенда (FastAPI, модели БД, очередь заданий, воркер), слой провайдеров модели, проверка токена Keycloak.
- Описания видов документов и правил проверки по разделу 4.1 ТЗ, подсказки модели.
- Интерфейсы соискателя и оператора, типы API по OpenAPI.
- Тексты документации — черновики ассистентов, правились людьми.

## Что делали руками
- Постановка задач, выбор архитектуры (очередь в Postgres, Keycloak, двухшаговый разбор) и приёмка результата.
- Эталонные ответы для тестовых файлов — размечались вручную.
- Развёртывание стенда, локальной модели и замеры на своём оборудовании.
- TODO (команда): каждый участник дописывает свою часть — что именно правил и проверял сам.

## Где ассистент ошибся и как заметили
- Подтверждено в коде/истории: библиотека PyMuPDF (AGPL) противоречит требованию к лицензиям — заметили при сверке с
  положением, заменили на pypdfium2 (ADR-006).
- Модели возвращают JSON не в той форме (поля на верхнем уровне вместо `fields`, значение вместо `{value, confidence}`) —
  заметили на реальном прогоне открытого набора, добавили терпимый разбор ответа и серверную валидацию.
- Правки оператора сначала не проходили серверные правила (даты, форматы) — заметили при ревью, теперь проходят ту же
  проверку, что и вывод модели.
