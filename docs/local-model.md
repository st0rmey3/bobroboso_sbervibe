# Переход на локальную модель (пошагово)

Зачем: заказчик хочет полностью отказаться от передачи документов во внешние сервисы. Локальная модель работает
на своём компьютере — документы никуда не уходят. Переключение делается только настройкой в `.env`, код не меняется:
все обращения к модели проходят через один слой `backend/app/llm/` (см. docs/llm.md).

Файлы для локального сервиса в репозитории:
- `docker-compose.yml` — сервис `ollama` (профиль `local-llm`);
- `Makefile` — цель `up-local-llm` (поднимает Ollama и скачивает модель);
- `backend/app/llm/ollama.py` — локальный провайдер (структурированный JSON-ответ по схеме);
- `backend/app/llm/ocr.py` — OCR-шаг: локальный (`OCR_PROVIDER=ollama`) или olmOCR (`OCR_PROVIDER=olmocr`).

## 1. Что нужно
| | Рекомендуется | Минимум |
|---|---|---|
| Видеокарта | NVIDIA с 8 ГБ видеопамяти (стенд: RTX 5060 8 ГБ) | без GPU работает на CPU, но в разы медленнее |
| ОЗУ | 16 ГБ | 8 ГБ (для модели 3B) |
| Диск | ~6 ГБ под `qwen2.5vl:7b` | ~3,2 ГБ под `qwen2.5vl:3b` |
| ПО | Docker Desktop + Ollama | |

Модель должна понимать изображения (vision): документы приходят фотографиями. Выбрали Qwen2.5-VL: умеет читать
кириллицу и латиницу, версия 7B в 4-битной сборке помещается в 8 ГБ видеопамяти, лицензия Apache-2.0.

## 2. Вариант А — Ollama на самом компьютере (с GPU, рекомендуется)
1. Установить Ollama: https://ollama.com/download (нативно — так используется видеокарта).
2. Скачать модель:
   ```bash
   ollama pull qwen2.5vl:7b        # на слабом железе: qwen2.5vl:3b
   ```
3. Проверить, что модель отвечает:
   ```bash
   ollama run qwen2.5vl:7b "Ответь одним словом: работает?"
   ```
4. В `.env`:
   ```
   LLM_PROVIDER=ollama
   OLLAMA_MODEL=qwen2.5vl:7b
   OLLAMA_URL=http://host.docker.internal:11434
   OCR_PROVIDER=none
   ```
5. Перезапустить бэкенд и воркер: `docker compose up -d backend worker`.

## 3. Вариант Б — Ollama в Docker (Linux-сервер)
```bash
make up-local-llm          # = docker compose --profile local-llm up -d + ollama pull
```
В `.env`: `LLM_PROVIDER=ollama`, `OLLAMA_URL=http://ollama:11434`, `OCR_PROVIDER=none`, затем
`docker compose up -d backend worker`. Для GPU в Docker нужен NVIDIA Container Toolkit.

## 3a. Локальный OCR (по желанию)
Можно разделить работу на два шага, как с olmOCR: локальная модель сначала распознаёт текст страницы,
затем из текста извлекаются поля. В `.env`:
```
LLM_PROVIDER=ollama
OCR_PROVIDER=ollama
OLLAMA_OCR_MODEL=            # пусто = та же OLLAMA_MODEL
```
`docker compose up -d backend worker`. Документ проходит дополнительную стадию «Распознавание текста», а в карточке
оператора под файлом появляется блок «Что прочитала модель» — распознанный текст.
Проверить отдельно: `docker compose exec worker python scripts/check_ocr.py <файл>` (для `OCR_PROVIDER=olmocr`).

## 4. Как проверить, что работает
1. `curl http://localhost:8000/api/health` → `"llm_provider": "ollama"`.
2. На http://localhost:3000 загрузить документ: статус проходит «В очереди → Подготовка → Извлечение данных →
   Проверка → Готово», в рабочем месте оператора видны поля рядом с оригиналом.
3. Логи воркера: `docker compose logs --tail 20 worker` → строки `document … → done`.
4. Если Ollama выключена — документ не «зависает» и не получает выдуманных данных: статус
   «Сервис распознавания временно недоступен, повторим автоматически», затем «недоступен» с кнопкой
   повторного разбора у оператора.

Вернуться на внешнюю модель: `LLM_PROVIDER=openai` и снова `docker compose up -d backend worker`.

## 5. Замеры
Внешняя модель (Qwen3.8-27B через OpenAI-совместимый API, открытый набор 23 файла, 10.10):
среднее время разбора файла — 8,2 с; 8 файлов параллельно; весь набор — 35 с; паспорта РФ/Беларуси/Индии, СНИЛС,
ИНН, ВУ, патент прочитаны верно; размытое фото и чек честно отбракованы.

Локальная модель (`qwen2.5vl:7b`, RTX 5060 8 ГБ): замеры на тех же файлах добавляются владельцем стенда (задача T-006).

## 6. Что меняется при переходе
| | Внешний сервис | Локальная модель |
|---|---|---|
| Железо | не нужно | GPU от 8 ГБ видеопамяти на сервере агентства |
| Скорость | ~8 с на файл, 8 параллельно | ожидаемо медленнее; параллельность ограничена одной видеокартой |
| Качество | высокое на чистых сканах и фото | модель меньше — больше полей уйдёт оператору на проверку (это видно по уверенности поля) |
| Стоимость | оплата за запросы | разовая покупка железа + электричество |
| Приватность | фото документов уходят во внешний сервис | документы не покидают сервер агентства |
