# Журнал решений

Формат: дата · решение · почему · альтернативы.

### ADR-001 · 2026-10-10 · Стек: FastAPI + PostgreSQL + React
Python удобен для работы с PDF/изображениями и моделями; FastAPI сам генерирует OpenAPI-контракт для фронтенда.
React + Vite + TypeScript — одно SPA с двумя независимыми интерфейсами (`/` и `/operator`).
Альтернативы: NestJS (слабее экосистема для разбора документов), серверный рендеринг (риск по Д3).

### ADR-002 · 2026-10-10 · Очередь заданий в PostgreSQL, без Redis
Таблица `jobs` + `SELECT … FOR UPDATE SKIP LOCKED` + аренда с истечением. Одно хранилище — нет рассинхрона между
очередью и данными, работа не теряется при перезапуске (Д4, Д7), параллельная обработка — несколькими потоками/воркерами.
Альтернативы: Celery/arq + Redis — лишний сервис, состояние «только в очереди» прямо запрещено критериями.

### ADR-003 · 2026-10-10 · Вход оператора через Keycloak (OIDC)
Стандартный протокол, роли, готовая форма входа; бэкенд проверяет токен сам (подпись, issuer, клиент, роль).
Альтернатива: собственные логин/пароль + сессии — больше кода, хуже проверяемость.

### ADR-004 · 2026-10-10 · Слой модели: интерфейс + три провайдера
`LLMProvider.complete_json(system, prompt, schema, images)`; реализации: Ollama (локальная), GigaChat (основная облачная:
данные соискателей — персональные, остаются в РФ), любой OpenAI-совместимый API. Выбор — переменной `LLM_PROVIDER`.

### ADR-005 · 2026-10-10 · Двухшаговый разбор: тип → поля
Сначала модель определяет тип и читаемость, затем извлекает поля по схеме этого типа. Точнее, чем один общий запрос,
и даёт честный отказ «не читается»/«тип не определён».

### ADR-006 · 2026-10-10 · Только разрешительные лицензии
Положение (п. 5.8.4) запрещает «вирусные» лицензии. PyMuPDF (AGPL) заменён на pypdfium2 (Apache-2.0/BSD).

### ADR-007 · 2026-10-10 · Схема БД через create_all, без миграций
На время хакатона: таблицы создаются при старте, изменение схемы → `make reset`. Экономит время; Alembic — после
стабилизации схемы.
