# Ограничения и планы

## Работает частично
- **Качество локальной модели.** Локальный вариант (`qwen2.5vl:7b` в Ollama на RTX 5060 8 ГБ) работает, но
  сравнение с облачной моделью по времени и точности — см. таблицу замеров в docs/local-model.md.
  Сомнительные поля в любом случае уходят на проверку оператору, а не подаются как верные.
- **OCR-этап.** Есть два варианта: olmOCR-2 Сбера (`OCR_PROVIDER=olmocr`) и локальный через Ollama
  (`OCR_PROVIDER=ollama`). Сервер olmOCR с площадки 10.10 принимал соединение, но не отвечал (проверка —
  `scripts/check_ocr.py`), поэтому на стенде работает `OCR_PROVIDER=none`: модель читает изображение сама.
  Локальный OCR — самый медленный режим (три обращения к модели на файл).
- **Скорость локальной модели на 8 ГБ.** Модель 7B с распознаванием изображений в 8 ГБ видеопамяти целиком не
  помещается; для стенда — `qwen2.5vl:3b`, 2 потока воркера, страницы 1024 px (docs/local-model.md).
- **GigaChat.** Провайдер написан, но проверен не на всех типах документов; основной путь — OpenAI-совместимый API
  и локальный Ollama.
- **Сверка между документами** (ФИО кириллицей/латиницей, дата рождения, ФИО из анкеты) — сделана; сравнение
  нечёткое (транслитерация + похожесть ≥ 0,75), поэтому редкие написания имён стоит проверять оператору.
- **Набор документов по стране** — по п. 4.1 ТЗ; виды из открытого набора (ВУ, паспорта Беларуси и Индии)
  поддержаны и определяются по содержимому, их распределение по странам ждёт ответа кейсодержателя.

## Не сделано сознательно
- Миграции БД: схема создаётся при старте (`create_all`). На живых данных нужен Alembic.
- Хранение файлов — только локальный том Docker; для продакшена нужно S3-совместимое хранилище.
- Очистка старых файлов и персональных данных по сроку хранения.
- Антивирусная проверка загрузок.
- Ограничение частоты запросов к публичному API (защита от злоупотреблений).
- HTTPS и боевые настройки Keycloak (на стенде `sslRequired: none`).

## Что делали бы в следующие 10 часов
1. Метрики и графики очереди (сейчас — счётчики в `/api/health` и логи с request id).
2. Alembic и тесты миграций.
3. Сверка данных между документами заявки и подсказки оператору.
4. Дообучение подсказок по результатам разметки закрытого набора; замеры на большем наборе.
5. Нагрузочный тест воркеров (сейчас проверено на 23 файлах, 8 потоков).
6. Роли оператора помимо «просмотр/правка» (например, отдельная роль для выгрузок персональных данных).
