# Сценарий для того, кто за стендом (Windows, PowerShell)

> В PowerShell `curl` — это не настоящий curl. Везде пишем **`curl.exe`**.
> **Никогда не выполнять на защите `docker compose down -v`** — это удалит все заявки.
> После правки `.env` всегда `docker compose up -d backend worker` — `restart` настройки **не** перечитывает.

## 0. За 30 минут до защиты
```powershell
cd C:\Users\chern\PycharmProjects\bobroboso_sbervibe
git pull
docker compose up -d --build
docker compose ps                                   # 5 сервисов Up: db, keycloak, backend, worker, frontend
curl.exe http://localhost:8000/api/health           # "status":"ok", "llm_provider":"openai"
docker compose logs worker | findstr "LLM:"         # LLM: openai (Qwen/Qwen3.8-27B); OCR: none (LLM reads images)
```
Открыть вкладки браузера:
1. http://localhost:3000 — кабинет соискателя;
2. http://localhost:3000/operator — войти (`operator` / пароль из `.env`), проверить список заявок;
3. окно **инкогнито** — для показа «без входа не пускает»;
4. http://localhost:8000/docs — на случай вопросов про API.

Окна терминала: (1) команды, (2) `docker compose logs -f --tail 20 worker` — живой лог воркера на экране.
Ollama запущена (для показа локального режима): `ollama ps`. Папки готовы: `case_docs`, `case_docs_small`
(6 файлов), пустая `judges` — сюда копируем файлы судей.

Прогон-«разминка» за 10 минут до начала (заодно прогревает всё):
```powershell
python backend/scripts/acceptance_run.py case_docs_small
```

## 1. Профили `.env` (меняем только эти строки)
**А. Облако — основной режим показа (качество):**
```
LLM_PROVIDER=openai
OCR_PROVIDER=none
WORKER_CONCURRENCY=8
IMAGE_MAX_SIDE=1800
```
**Б. Локально, ничего не уходит наружу (показ п. 5.3 / С20):**
```
LLM_PROVIDER=ollama
OLLAMA_MODEL=qwen2.5:3b
OCR_PROVIDER=tesseract
WORKER_CONCURRENCY=2
```
**В. Внешний OCR Сбера (только если сервер оживёт):** `OCR_PROVIDER=olmocr`.

Переключение (одинаково для любого профиля):
```powershell
docker compose up -d backend worker
docker compose logs worker | findstr "LLM:"         # убедиться, что включилось нужное
curl.exe http://localhost:8000/api/health           # llm_provider сменился
```
Затем загрузить 1–2 файла на http://localhost:3000 и показать, что дошли до «Готово». После показа — **вернуть
профиль А**.

## 2. Что показывать по сценариям (порядок — coord/defense.md)
| Сценарий | Что делаешь | Что видят судьи |
|---|---|---|
| С1–С3 соискатель | Выбрать страну → набор документов меняется → выбрать файлы → «Отправить комплект» | Квитанция с номером заявки, статусы меняются сами |

| С6 дозагрузка | Обновить страницу → добавить файл в ту же заявку | Заявка восстановилась, файл добавился |
| С7 вид по содержимому | Файл в «Другой документ — определим сами» | Появился правильный раздел (например, паспорт Беларуси) |
| С8–С9 непригодные | Загрузить `Чек (не документ)` и `Размытое фото` | «Не читается» с понятной причиной, без выдуманных полей |

С13 — команда (подставить id любого документа из адреса карточки / API):

```powershell
curl.exe -i http://localhost:8000/api/operator/stats               # 401
```

## 3. Сбой модели (С10) — безопасный способ
1. В `.env` временно: `OPENAI_BASE_URL=http://127.0.0.1:9/v1` → `docker compose up -d backend worker`.
2. Загрузить файл → статус «Сервис распознавания временно недоступен, повторим автоматически».
   Через ~30–40 с (3 попытки) → «Ошибка разбора»: «Сервис распознавания недоступен. Оператор может перезапустить разбор.»
3. Вернуть `OPENAI_BASE_URL=https://llm.ilons.ru/v1` → `docker compose up -d backend worker`.
4. В карточке оператора нажать «Разобрать заново» → «Готово».

## 4. Правки вживую (С22) — как пересобрать
Рецепты (что править) — coord/defense.md, «Четыре правки». После правки:
```powershell
docker compose up -d --build backend worker          # правка в backend/
docker compose up -d --build frontend                # правка в frontend/ (1–2 минуты)
```
Потом обновить страницу браузера (Ctrl+F5) и показать результат. Закоммитить правку после показа.

## 5. Если что-то сломалось во время защиты
| Симптом | Что делать |
|---|---|
| `/operator` → «Не удалось открыть страницу входа» | `docker compose up -d --force-recreate keycloak`, подождать минуту |
| Документы висят в «В очереди» | `docker compose logs --tail 30 worker` → если ошибка модели — переключить профиль (облако ↔ локально) |
| Облачная модель не отвечает | Профиль Б (локально) — это и есть демонстрация готовности к локальной модели |
| Всё странно | `docker compose up -d` (без `down -v`!); данные сохранятся |
| Нужно показать, что включено сейчас | `docker compose logs worker \| findstr "LLM:"` и `curl.exe http://localhost:8000/api/health` |
