## 1. Рассказ за 60 секунд
«Бэкенд — FastAPI на Python, данные в PostgreSQL, файлы — в томе Docker. Соискатель загружает файл — сервер **сразу**
проверяет его (размер, настоящий тип по сигнатуре, дубликат, лимиты), сохраняет и отвечает `202`, ничего не ожидая.
Разбор делает **отдельный процесс-воркер**: он забирает задание из таблицы `jobs` в Postgres, сначала спрашивает модель
«что это за документ и читается ли он», потом «извлеки поля этого вида», и сервер проверяет поля по правилам ТЗ.
Все обращения к модели — в одном слое `backend/app/llm/`, провайдер меняется переменной в `.env`. Если воркер упал —
задание не теряется: оно в БД под арендой, которая истекает. Рабочее место оператора закрыто Keycloak: каждый запрос
проверяет токен на сервере».

## 3. Путь одного документа (главное, что спросят)
1. **Загрузка** `POST /api/public/applications/{id}/documents` → `upload_document`. Проверки на сервере:
   токен заявки → вид документа из справочника (или пусто — «определим сами») → лимит файлов → размер → общий объём →
   **тип по первым байтам файла** (`sniff_mime`, не по расширению) → дубликат по sha256. Каждый отказ пишется в журнал
   (`_reject` → `audit`). Файл сохраняется в том, создаются `Document(queued)` и `Job(queued)` в **одной транзакции** →
   ответ `202` за десятки миллисекунд. **Модель здесь не вызывается.**
2. **Воркер** (`worker.loop`) в 8 потоках вызывает `queue.claim`: `SELECT … FOR UPDATE SKIP LOCKED` — два потока не
   возьмут одно задание; задание получает аренду `locked_until = сейчас + 60 с`.
3. Пока идёт разбор, поток `_keepalive` каждые 15 с продлевает аренду.
4. `process_document`: стадии сохраняются в БД (их видит интерфейс): `preprocessing` (PDF → картинки, поворот фото по
   EXIF) → `recognizing` (только если включён OCR) → `extracting`.
5. **Вызов 1** — `classify_prompt`: «какой это из видов и читается ли». Нечитаемо → `unreadable` с причиной от модели;
   не документ (чек) → `unreadable`; вид определён → дальше.
6. **Вызов 2** — `extract_prompt` + JSON-схема полей этого вида → модель возвращает `{поле: {value, confidence}}`.
7. **Проверка на сервере** `validate`: цифры без пробелов, даты к ГГГГ-ММ-ДД, формат (серия — 4 цифры, номер — 6…),
   правила `not_future` / `not_expired` / `latin`; истёкший документ **принимается и помечается**. Итог `done` или
   `needs_review` с русской причиной. Заявке пересчитывается статус (`refresh_status`).
8. **Оператор** видит в карточке поля, собранные со всех файлов документа (`doc_slots`): лицо и оборот патента дают
   одно целое; для каждого поля берётся значение с правкой оператора, иначе — с наибольшей уверенностью.

## 4. Модель данных
- `applications`: ФИО, телефон, страна, набор обязательных видов, **хэш** токена соискателя, статус заявки.
- `documents`: файл (имя, тип, размер, sha256, ключ в хранилище), заявленный/определённый вид, статус и причина,
  поля JSON `{value, confidence, issues, edited_by}`, текст OCR, время разбора.
- `jobs`: задание разбора — статус, попытки, `run_after` (когда можно повторить), `locked_by` / `locked_until` (аренда).
- `audit_events`: кто (`applicant` / `system` / `operator:<логин>`), что, когда, детали — журнал для судей.
- Статусы документа: `queued → preprocessing → (recognizing) → extracting → validating → done | needs_review |
  unreadable | failed`. Схема БД создаётся при старте (`create_all`), миграций нет — ADR-006.

## 5. Очередь и устойчивость (С11–С12, Д4, Д7)
- **Почему не Redis/Celery:** критерии запрещают «состояние только в очереди»; одно хранилище — нет рассинхрона (ADR-002).
- **Параллельность:** `WORKER_CONCURRENCY` потоков (8 для облака, 2 для локальной видеокарты); `SKIP LOCKED`
  раздаёт разные задания разным потокам и даже разным контейнерам воркера.
- **Воркер убили (`kill -9`, перезапуск):** задание осталось `running` в БД. При старте воркер вызывает `release_own` —
  свои незаконченные задания сразу в очередь. Если упал совсем другой воркер — его аренда истечёт через ≤60 с, и
  задание заберёт любой живой (`claim` берёт и `queued`, и `running` с истёкшей арендой).
- **Модель недоступна / таймаут / мусор вместо JSON:** провайдер бросает `LLMError(retryable=True)` → `retry_or_fail`:
  повтор через 10 с, потом 20 с; после `JOB_MAX_ATTEMPTS=3` → `failed` с русской причиной и кнопкой «Разобрать
  заново» у оператора. **«Готово» без успешного ответа модели не бывает.**
- **Ошибка в нашем коде:** ловится отдельно, так же повтор → `failed` «Внутренняя ошибка разбора»; процесс не падает.
- Проверено вживую: 23 файла, `kill -9` на 6-й секунде → все дошли до конца за 35 с.

## 6. Слой модели (раздел 5.3, С19–С20, 15 баллов)
- Интерфейс один: `LLMProvider.complete_json(system, prompt, schema, images) → LLMResponse`. Остальной код знает только
  `get_provider()` и `LLMError`. Ни в обработчиках API, ни во фронтенде вызовов модели нет.
- Провайдеры: `openai` (Qwen3.8-27B Сбера, OpenAI-совместимый API, читает картинки), `ollama` (локально),
  `gigachat`. Выбор — `LLM_PROVIDER` в `.env`; смена без правки кода, только `docker compose up -d backend worker`.
- OCR отдельно (`OCR_PROVIDER`): `none` — модель сама читает картинку (по умолчанию); `olmocr` — olmOCR-2 Сбера;
  `ollama` — локальная модель как OCR; `tesseract` — классический OCR на процессоре + текстовая модель.
- Промпты — в репозитории (`extraction/prompts.py`), общие для вида документа, без значений из образцов.
- Устойчивость к ответу модели: `parse_json` снимает ```-обёртку и вытаскивает JSON; `fields_from` принимает поля и
  на верхнем уровне; значение без `{value, confidence}` тоже понимается.
- Что меняется при переходе на локальную — docs/local-model.md §6: железо, скорость, качество, стоимость, приватность.

## 7. Разбор, проверки, сверка (С7–С10, 30 баллов)
- **Вид — только по содержимому.** Имя файла в модель не передаётся; `acceptance_run.py` загружает файлы вообще без
  указания вида — модель определила 8 из 8 видов открытого набора.
- **Минимум полей ТЗ** (`required=True` в `doctypes.py`) проверяется по документу целиком (лицо + оборот), а не по
  каждому файлу: на лицевой стороне патента нет срока действия — это не ошибка, он на обороте.
- **Дубликаты:** тот же файл → отказ при загрузке (sha256); тот же документ другим файлом («копия файла») →
  замечание по совпавшим серии и номеру (`_duplicate_warnings`).
- **Сверка между документами** (`crosscheck.py`): ФИО переводится в латиницу, сглаживаются варианты (KH/H, Y/I),
  слова сравниваются один к одному с похожестью ≥ 0,75, отчество может отсутствовать. Сравнивается: ФИО из анкеты
  с каждым документом, документы между собой, даты рождения. Расхождение → предупреждение и статус «Требует
  внимания», **без автоотказа**.
- **Правка оператора** проходит те же серверные правила (`update_fields` → `validate`): исправленная дата, если она
  уже истекла, всё равно получит «Срок действия истёк».

## 8. Безопасность (Д2, Д8)
- **Оператор:** `require_operator` на уровне всего роутера `/api/operator/*` (включая файлы и CSV). Проверяется:
  подпись токена по ключам Keycloak (JWKS), издатель (`OIDC_ISSUER`), срок, клиент `azp=operator-ui`, роль `operator`.
  Подделка/истёк/чужой клиент → 401, нет роли → 403. Покрыто `tests/test_auth.py`.
- **Соискатель:** регистрации нет (ТЗ). При создании заявки — случайный токен 32 байта, отдаётся один раз, в БД только
  sha256-хэш. Без токена/с чужим токеном/несуществующий id → одинаковый 404 (нельзя даже узнать, есть ли заявка).
  Соискателю распознанные поля паспорта **не отдаются** вообще.
- **ПДн:** оригиналы только через API оператора; каждое открытие оригинала — запись `file_viewed` в истории;
  значения полей не пишутся в логи; CSV защищён от формул Excel.
- **Секреты:** только в `.env` (в `.gitignore`), в репозитории — `.env.example` без значений.
- **Лицензии:** только разрешительные (п. 5.8.4) — PyMuPDF (AGPL) заменили на pypdfium2.

## 9. Наблюдаемость
- У каждой строки лога API — id запроса (`X-Request-ID`), у воркера — id задания; логируются стадии и время.
- `GET /api/health` — база, провайдер, очередь в цифрах. При старте воркер пишет `LLM: …; OCR: …`.
- Оператору: экран «В работе» (`/api/operator/processing`, `/stats`) — реальные задания, попытки, причины.

## 11. Вопросы судей — короткие ответы
1. *Почему 202, а не 200?* — «Принято, обработка позже»: разбор асинхронный.
2. *Что если два воркера возьмут одно задание?* — Не возьмут: `FOR UPDATE SKIP LOCKED` блокирует строку.
3. *Почему аренда 60 с, а не «пока не закончит»?* — Иначе после падения задание висело бы вечно; продление каждые 15 с.
4. *Где гарантия, что тип не по имени файла?* — В модель уходят только картинки страниц; покажу загрузку без вида.
5. *Модель выдумала значение?* — Уверенность по каждому полю, серверные правила, оператор видит оригинал рядом;
   сомнительное (< 0,6) подсвечено и переводит документ в «Требует проверки».
6. *Модель вернула не JSON?* — `parse_json` → `LLMError` → повтор → честный `failed`.
7. *Как переключиться на локальную?* — `LLM_PROVIDER=ollama` в `.env`, `docker compose up -d backend worker`.
8. *Почему два вызова модели, а не один?* — Честный отказ «не читается / не документ» и схема полей под конкретный вид
   (ADR-005); цена — время, компенсируем параллельностью.
9. *Как хранится токен соискателя?* — Только хэш; сравнение `hmac.compare_digest`.
10. *Можно ли без входа скачать оригинал?* — Нет: 401; покажу `curl` без токена.
11. *Что будет при перезапуске всего стенда?* — Postgres и том файлов сохраняются; задания продолжатся.
12. *Как работает сверка ФИО латиницей и кириллицей?* — §7, функция `same_person`.
13. *Почему Keycloak?* — Требование организаторов; стандарт OIDC; проверка токена — наша, на сервере.
14. *Как добавить новый вид документа?* — Одна запись `DocType` в `doctypes.py` (+ страна в `COUNTRIES`); схема
    запроса к модели, промпт и интерфейс строятся из реестра автоматически.
15. *Чем рискуете?* — §12.

## 12. Честные слабые места
- Нет миграций БД (изменение схемы = сброс), нет ограничения частоты на публичном API, токен соискателя в
  `localStorage` и без срока, локальная модель на 8 ГБ медленная, olmOCR Сбера с площадки не отвечал,
  соответствие «вид документа ↔ страна» для видов открытого набора ждёт ответа кейсодержателя.

## 13. Команды на защите
```
docker compose ps                                     # всё живо
curl http://localhost:8000/api/health                 # провайдер и очередь
curl -i http://localhost:8000/api/operator/stats      # без входа → 401
docker compose restart worker                         # во время разбора — работа продолжится

```

(`public.py`); новое поле — `FieldSpec` в `DOC_TYPES`.
